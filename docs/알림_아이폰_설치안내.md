# 🍎 아이폰 앱 알림 설치 안내

아이폰 앱(App Store 에서 받은 TCS)에서 알림이 오게 하는 절차입니다.
브라우저(크롬·사파리·안드로이드)는 `docs/알림_설치안내.md` 쪽입니다.

> **왜 따로 하나요?**
> 아이폰 앱은 웹 화면을 통째로 담고 있지만, 그 안에서 웹푸시는 통하지
> 않습니다. 애플이 앱 안의 웹 화면(WKWebView)에는 서비스워커 푸시를
> 주지 않기 때문입니다. 애플 길(APNs)로 따로 보내야 합니다.
> 받는 쪽 설정(켜기·미리보기·나를 부른 것만·방마다 끄기)은 똑같이 씁니다.

## 0. 먼저 — 웹 알림이 깔려 있어야 합니다

`db/알림_푸시_DB설치.sql` 을 아직 안 하셨다면 그것부터 하세요.
아이폰 설치는 그 표에 칸을 하나 더 붙이는 일입니다.

```
 길   | 기기 수

```

## 2. 애플 인증 키(.p8) 만들기 (5분)

알림을 보내려면 애플에게 "나 TCS 주인 맞다" 고 증명해야 합니다.
그 증명서가 **APNs 인증 키**입니다. 한 번 만들면 모든 앱에 계속 씁니다.

1. <https://developer.apple.com/account/resources/authkeys/list> 로 들어갑니다
2. **키(Keys)** 옆의 **＋** 를 누릅니다
3. **Key Name** 에 `TCS Push` 라고 적습니다
4. **Apple Push Notifications service (APNs)** 에 체크합니다
5. 빨간 글씨로 *"This service must have environment and type configured"* 가
   뜹니다. 오른쪽 **Configure** 를 누르고 두 가지를 고릅니다:

   | 항목 | 고를 것 | 왜 |
   |---|---|---|
   | **Key Environment** | **Sandbox & Production** (둘 다) | Xcode 로 직접 돌린 앱은 Sandbox, 앱스토어·TestFlight 앱은 Production 입니다. 하나만 고르면 다른 쪽에서 `BadDeviceToken` 으로 막힙니다 |
   | **Key Restriction** | **Team Scoped (All Topics)** | 앱마다 키를 새로 만들 필요가 없습니다. 이미 올리신 다른 앱들에도 그대로 씁니다 |

6. **Save** → **Continue** → **Register**
7. **Download** 를 누릅니다 → `AuthKey_XXXXXXXXXX.p8` 파일이 받아집니다

> ⚠️ **이 파일은 딱 한 번만 받을 수 있습니다.** 다시 받을 수 없어요.
> 안전한 곳에 보관하세요. **깃허브에 절대 올리지 마세요** —
> 이게 남의 손에 들어가면 누구든 TCS 이름으로 아이폰에 알림을
> 뿌릴 수 있습니다. (`.gitignore` 에 `AuthKey_*.p8` 로 막아 두었습니다)

받고 나면 그 화면에 **Key ID** 가 10글자로 적혀 있습니다 (예: `ABC123DEFG`).
파일 이름 `AuthKey_ABC123DEFG.p8` 의 가운데 글자와 같습니다. 적어 두세요.

### Team ID 는 어디에?

<https://developer.apple.com/account> → 오른쪽 위 **Membership details**.
**Team ID** 가 10글자로 적혀 있습니다 (예: `9XYZ8ABCDE`).

## 3. Supabase 에 비밀값 넣기 (2분)

`.p8` 파일이 있는 폴더에서 터미널을 열고, **한 줄씩** 그대로 붙여넣으세요.
(`XXXXXXXXXX` 자리에는 2번에서 적어 둔 값을 넣습니다)

```bash
cd ~/imessenger
supabase link --project-ref bbfvnmlrdtzmcwfadjqw
```

```bash
supabase secrets set APNS_KEY_ID=ABC123DEFG
```

```bash
supabase secrets set APNS_TEAM_ID=9XYZ8ABCDE
```

```bash
supabase secrets set APNS_BUNDLE_ID=io.github.koreayjk.tcs
```

```bash
supabase secrets set APNS_PRIVATE_KEY="$(grep -v -- '-----' ~/Downloads/AuthKey_ABC123DEFG.p8 | tr -d '\n\r ')"
```

> `cat` 을 그대로 쓰면 줄바꿈과 머리말이 같이 들어가는데, 그 과정에서
> 따옴표나 캐리지리턴이 섞여 `Failed to decode base64` 로 막히는 일이
> 있습니다. 위 명령은 머리말과 줄바꿈을 떼고 한 줄로 넣습니다.
> (함수 쪽에서도 섞인 글자를 걷어내게 해 두었지만, 넣을 때부터
> 깔끔한 편이 낫습니다)

> `#` 로 시작하는 설명을 명령 뒤에 붙이지 마세요. 맥 터미널(zsh)은
> 그걸 설명으로 보지 않고 명령의 일부로 읽어서 엉뚱한 곳에서 멈춥니다.

> **프로젝트를 꼭 확인하세요.** TCS 는 `bbfvnmlrdtzmcwfadjqw` 입니다.
> `supabase link` 를 먼저 하지 않으면 터미널이 목록을 보여주며 고르라고
> 하는데, 거기서 다른 프로젝트를 고르면 비밀값이 엉뚱한 데로 갑니다.

확인:

```bash
supabase secrets list
```

`APNS_KEY_ID` · `APNS_TEAM_ID` · `APNS_BUNDLE_ID` · `APNS_PRIVATE_KEY`
네 개가 보이면 됩니다. (값은 안 보이는 게 정상입니다)

## 4. 보내는 함수 올리기 (1분)

```bash
cd ~/imessenger
git pull
supabase functions deploy push-notify
```

같은 함수가 브라우저(웹푸시)와 아이폰(APNs) 둘 다 보냅니다.
받는 사람 기기에 맞춰 알아서 갈라집니다.

---

## 5. Xcode 에서 알림 기능 켜기 (2분)

```bash
cd ~/imessenger
git pull
npm install
npm run ios
```

Xcode 가 열리면:

1. 왼쪽 맨 위 파란 **App** 아이콘을 클릭
2. 가운데 **TARGETS → App** 선택
3. 위쪽 탭에서 **Signing & Capabilities**
4. **＋ Capability** 를 누르고, 뜨는 목록에서 **Push Notifications** 를 더블클릭
5. 목록에 `Push Notifications` 줄이 생기면 된 겁니다

> 이 단추 하나가 두 가지를 같이 해줍니다 — 앱에 권한을 붙이고,
> 애플 개발자 사이트의 App ID 에도 푸시를 켜 줍니다.
> 손으로 파일을 고치지 말고 꼭 이 단추로 하세요.

그다음 ▶ (실행) 을 눌러 아이폰에 올립니다.

---

## 6. 되는지 보기

1. 아이폰에서 TCS 를 엽니다
2. **내 프로필 → 🔔 알림 → 알림 켜기** → 아이폰이 묻는 창에 **허용**
3. 같은 화면 아래 **앱을 닫아도 알림 받기** 의 **켜기** 를 누릅니다
4. **앱을 완전히 닫습니다** (위로 쓸어 올려서 끄기)
5. 다른 기기에서, 그 사람이 들어 있는 채팅방에 메시지를 하나 보냅니다
6. 아이폰에 알림이 떠야 합니다. 누르면 그 채팅방이 열립니다

## 안 될 때

**아무 알림도 안 온다**

Supabase → Edge Functions → `push-notify` → **Logs** 를 봅니다.

| 로그에 보이는 말 | 뜻과 할 일 |
|---|---|
| `APNs 실패 403 InvalidProviderToken` | `APNS_KEY_ID` 나 `APNS_TEAM_ID` 가 틀렸습니다. 3번을 다시. |
| `APNs 실패 403 ExpiredProviderToken` | 맥·서버 시계가 많이 틀어져 있습니다. 거의 안 납니다. |
| `APNs 실패 400 TopicDisallowed` | `APNS_BUNDLE_ID` 가 앱과 다릅니다. Xcode 의 Bundle Identifier 와 같아야 합니다. |
| `APNs 실패 400 BadDeviceToken` | 아래 '개발용/배포용' 을 보세요. |
| `APNs 던짐 ... Failed to decode base64` | `APNS_PRIVATE_KEY` 에 base64 아닌 글자가 섞였습니다. 위 3번의 `grep … tr` 명령으로 다시 넣으세요. |
| `APNS_PRIVATE_KEY 를 읽을 수 없습니다 (…)` | 같은 문제입니다. 괄호 안 길이가 0 에 가까우면 값이 잘려 들어간 것입니다. |
| `APNS_PRIVATE_KEY 가 애플 키 모양이 아닙니다` | base64 는 읽혔는데 P-256 키가 아닙니다. `.p8` 파일을 제대로 넣었는지 보세요. |
| `APNs 실패 410` | 그 기기가 앱을 지웠습니다. 저절로 치워집니다. |
| 아무 줄도 없다 | 보내는 쪽에서 함수를 안 불렀습니다. `git pull` 후 새로 빌드했는지 보세요. |

**개발용 / 배포용 (BadDeviceToken)**

Xcode 로 직접 돌린 앱의 기기 표는 애플의 **sandbox** 쪽에서만 받고,
TestFlight·앱스토어로 받은 앱은 **production** 쪽에서만 받습니다.
함수는 기본으로 production 을 먼저 보고, 거절당하면 sandbox 로 한 번 더
넣어 보니 둘 다 됩니다. 한쪽으로 고정하고 싶으면:

```bash
supabase secrets set APNS_ENV=sandbox
```

(앱스토어에 올린 뒤에는 `APNS_ENV=production` 또는 그냥 지우세요)

**'켜기' 를 눌러도 안 켜진다**

- 아이폰 **설정 → TCS → 알림** 이 꺼져 있지 않은지 보세요.
  한 번 '허용 안 함' 을 누르면 앱이 다시 묻지 못합니다.
- 시뮬레이터에서는 기기 표가 안 나옵니다. **진짜 아이폰**으로 하세요.

**앱이 켜져 있을 때도 알림이 뜬다**

맞습니다. 아이폰은 앱이 켜져 있어도 애플이 띄웁니다.
보고 있는 방의 알림까지 뜨는 게 거슬리면 알려주세요 — 막을 수 있습니다.

## 안드로이드 앱은?

지금은 안 됩니다. 안드로이드 앱(TWA)은 크롬이 그대로 돌리는 구조라
웹푸시가 그대로 통합니다. `twa-manifest.json` 의 `enableNotifications`
를 켜 두었으니, 다음 번 AAB 를 새로 만들어 올리면 됩니다.
