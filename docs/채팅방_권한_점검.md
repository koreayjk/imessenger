# 🔒 채팅방 권한 점검 결과

> "학생이 1:1이 아닌 그룹방을 만들면 거기에 다른 사람을 초대해서 대화가
> 가능한 거 같은데 이거 체크해줘"

**맞습니다.** 그리고 생각하신 것보다 넓게 열려 있었습니다.

---

## 어떻게 확인했나

추측하지 않았습니다. 지역 데이터베이스에 **지금 쓰고 있는 정책을 그대로**
깔고(`db/전체잠그기_RLS.sql` + `db/신고차단_DB설치.sql`), 학생 계정으로
로그인해서 여덟 가지를 직접 해봤습니다.

## 결과 — 여덟 가지 다 됐습니다

| | 해본 것 | 고치기 전 | 고친 뒤 |
|---|---|---|---|
| ① | 내가 없는 방(교사 전용방·남의 1:1)이 목록에 보이나 | **다 보임** | 0개 |
| ② | 남의 1:1 대화 내용이 읽히나 | **읽힘** | 0줄 |
| ③ | 학생이 단체방을 만들 수 있나 | **됨** | 막힘 |
| ④ | 거기에 다른 학생을 초대할 수 있나 ← 물어보신 것 | **됨** | 막힘 |
| ⑤ | 내가 없는 교사 전용방에 나를 밀어넣을 수 있나 | **됨** | 막힘 |
| ⑥ | 남의 1:1 방에 글을 쓸 수 있나 | **됨** | 막힘 |
| ⑦ | 선생님을 교사 전용방에서 내쫓을 수 있나 | **됨** | 0줄 |
| ⑧ | 교사 전용방을 통째로 지울 수 있나 | **됨** | 0줄 |

화면에서 눈에 띄는 건 ③④뿐이지만, **나머지도 브라우저 주소창에서 바로
됩니다.** 앱을 거치지 않고 데이터베이스에 직접 말을 걸 수 있기 때문입니다.

## 왜 이렇게 됐나

`'학생끼리는 1:1 대화를 할 수 없어요'` 라는 규칙이 **화면에만 적혀**
있었습니다. 데이터베이스는 아무것도 막고 있지 않았습니다.

뿌리는 `my_channel_ids()` 라는 함수였습니다. 이름은 '내 채팅방' 인데
내용은 **'우리 공동체의 모든 방'** 이었습니다. 메시지·채널멤버 정책이
전부 이 함수에 기대고 있어서, 한 군데가 넓으니 전부 같이 넓어졌습니다.

## 고친 뒤 규칙

| | 방 목록 | 대화 내용 | 단체방 만들기 | 남을 넣고 빼기 |
|---|---|---|---|---|
| **총·부총관리자** | 전부 | 전부 (지켜봄) | ○ | ○ |
| **관리자·행정·교사·간사** | 단체방 전부 | **내가 들어간 방만** | ○ | ○ |
| **학생·학부모** | 내가 들어간 방만 | 내가 들어간 방만 | ✕ | ✕ |

- **1:1 방은 목록조차 교직원에게 안 보입니다.** 누가 누구와 이야기하는지가
  이미 사생활입니다. 총·부총관리자만 지켜봅니다 — 지금까지의 약속 그대로입니다.
- **학생은 선생님·간사님과 1:1 은 그대로 할 수 있습니다.** 학생끼리만 막힙니다.
- **1:1 방에는 두 사람까지.** 세 번째를 끼워넣으려 하면 방아쇠가 막습니다.

### 신고함은 그대로 돌아갑니다

읽기를 좁히면 **신고함이 통째로 막힙니다.** 교직원이 신고된 메시지를
가리거나 지우려면 그 줄을 읽을 수 있어야 하는데(가리기의 `RETURNING` 도
읽기 규칙을 탑니다), 그 방에 안 들어가 있으면 못 읽게 되기 때문입니다.
지역에서 실제로 막히는 것을 보고 구멍 하나만 정확히 열었습니다:

> **내가 들어가 있지 않은 방의 메시지 중 읽히는 것은 '누군가 신고한 줄' 뿐입니다.**

확인한 것 — 교사가 전혀 안 끼어 있는 1:1 방에서:

| | |
|---|---|
| 방이 목록에 보이나 | ✕ |
| 신고된 글을 읽나 | ○ |
| **바로 옆의 신고 안 된 글을 읽나** | **✕** |
| 신고된 글을 가리나 | ○ |
| 신고 안 된 글을 지우나 | ✕ (0줄) |

**내가 들어가 있는 방에서는 예전처럼 자유롭게 조정합니다** — 신고가
없어도 가리고 지울 수 있습니다.

## 🖥 설치

```bash
cd ~/imessenger && git pull origin main && cat db/채팅방_권한_잠그기.sql | pbcopy
```

→ 🗄 Supabase **SQL Editor** 에 붙여넣고 **Run**

두 번 돌려도 안전합니다. 세 번 연속 돌려서 확인했습니다.

> 이 파일은 혼자서도 됩니다. `db/신고차단_DB설치.sql` 이나
> `db/전체잠그기_RLS.sql` 을 아직 안 돌리셨어도, 필요한 도우미 함수를
> 같이 만듭니다.

### ⚠️ 설치 뒤에 한 번 봐주실 것

방을 **만든 사람**(`created_by`)을 새로 적기 시작합니다. 예전 방들은 비어
있는데, 멤버 줄로 찾으니 문제는 없습니다. 다만 **멤버가 한 명도 없는 단체방**이
있다면 그 방은 총·부총관리자 외에는 안 보이게 됩니다. 채팅 목록에서
안 보이는 방이 생기면 **관리자 → 채널 관리** 에서 멤버를 넣어주세요.

## 👁 같이 들어간 것 — 지켜보는 방

> "총리더라 1:1채팅방과 단톡방이 다 보이잖아 이거 때문에 내 진짜 채팅방이
> 뒤죽박죽이야"

**내가 들어가 있지 않은 방**은 목록 **맨 아래**로 내리고 **접어** 두었습니다.
`👁 지켜보는 방 (N)` 줄을 누르면 펼쳐집니다. 접고 편 것은 기억합니다.

- 펼치면 **새 글 있는 방이 먼저**, 그 다음 단체방 → 1:1, 이름 차례입니다
- 그 줄에 지켜보는 방들의 **새 글 수**가 회색으로 적힙니다
- **사이드바 채팅 숫자와 브라우저 제목 숫자는 내 방 것만 셉니다.**
  지켜보는 방까지 세면 늘 세 자리라 아무 뜻이 없어집니다
- 검색할 때도 똑같이 내 방이 먼저, 지켜보는 방은 아래로 모입니다

총·부총관리자가 아니면 이 줄은 **아예 나오지 않습니다.**
