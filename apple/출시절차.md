# 애플 App Store 출시 절차 — TCS

이미 앱 두 개를 올려 보셨으니 계정·결제 단계는 건너뜁니다.
여기는 **TCS 만의 사정**과 **안드로이드와 다른 점**만 적습니다.

---

## ⚠️ 먼저 — 가장 큰 위험은 심사 지침 4.2 입니다

구글은 웹 껍데기(TWA)를 공식으로 받아줍니다. **애플은 그걸 반려 사유로 씁니다.**

> **4.2 Minimum Functionality** — 웹사이트를 그대로 포장한 앱은
> App Store 에 올릴 수 없습니다.

그래서 이 프로젝트는 두 가지를 다르게 했습니다.

1. **원격 주소를 띄우지 않고 화면을 앱 안에 넣습니다.**
   `capacitor.config.json` 에 `server.url` 이 없습니다. 비행기 모드에서도
   앱이 뜨고, 심사 중에 사이트가 흔들려도 앱은 멀쩡합니다.
   대신 **화면을 고치면 App Store 에 새 버전을 올려야 반영됩니다.**
   (안드로이드는 `main` 에 밀면 바로 반영됩니다 — 여기서 갈립니다)

2. **네이티브 껍데기(Capacitor)를 씁니다.** 카메라·사진 보관함 권한을
   제대로 선언하고, 네이티브 스플래시를 띄웁니다.

3. **푸시 알림과 앱 아이콘 숫자가 들어 있습니다.** (2026-10 추가)
   애플 APNs 로 직접 받고, 안 읽은 수가 아이콘에 숫자로 붙습니다.
   **이건 사파리로는 못 합니다.** 4.2 는 "웹사이트를 그대로 포장했나" 를
   묻는 조항이라, 웹에서 안 되는 기능이 실제로 있다는 게 가장 센 답입니다.
   심사 노트에 한 줄 적어 두면 좋습니다:

   ```
   This app delivers Apple push notifications and badges the app icon
   with the unread count — neither is available on the website.
   ```

4. **맥 앱은 따로 있습니다.** `desktop/` 의 .dmg 는 App Store 와 무관하게
   직접 나눠 주는 것이라, 이 심사에 영향을 주지 않습니다.

## 1. 맥에서 열기

```bash
git pull
npm install          # 처음 한 번
npm run ios          # www/ 만들고 → 동기화 → Xcode 열림
```

`npm run sync` 는 `index.html` 을 `www/` 로 추린 뒤 앱 안에 복사합니다.
**화면을 고쳤으면 Xcode 를 열기 전에 반드시 다시 돌리세요.** 안 그러면
예전 화면이 그대로 들어갑니다.

| 값 | |
|---|---|
| Bundle ID | `io.github.koreayjk.tcs` |
| 최소 iOS | 15.0 |
| 버전 | 1.0 (빌드 1) |

---

## 2. Xcode 서명

`App` 타겟 → **Signing & Capabilities**

- **Automatically manage signing** 켜기
- **Team** — 쓰시는 조직 계정 선택
- Bundle Identifier 가 `io.github.koreayjk.tcs` 인지 확인

이 Bundle ID 가 개발자 계정에 아직 없으면 Xcode 가 알아서 만듭니다.

## 4. 빌드 올리기

> 🔁 **Archive 전에 `npm run ios` 를 다시 돌렸는지 확인하세요.**
> 화면은 앱 안에 들어 있어서, 동기화를 안 하면 **고치기 전 화면이**
> 그대로 심사에 올라갑니다. 확인은 한 줄로 됩니다:
>
> ```bash
> md5 index.html ios/App/App/public/index.html
> ```
>
> 두 값이 **같아야** 합니다. 다르면 `npm run ios` 를 먼저 돌리세요.

Xcode 에서 기기를 **Any iOS Device (arm64)** 로 바꾸고:

```
Product → Archive
  → Distribute App → App Store Connect → Upload
```

올라간 뒤 App Store Connect 에 뜨기까지 10~30분 걸립니다.

> 수출 규정 질문은 안 나옵니다. `Info.plist` 에
> `ITSAppUsesNonExemptEncryption = false` 를 넣어 뒀습니다.
> (HTTPS 만 쓰므로 면제 대상입니다)

## 5. ⚠️ 심사용 데모 계정 — 빠뜨리면 반드시 반려됩니다

**App Review Information → Sign-in required 체크**

TCS 는 로그인해야 아무것도 안 보이는 앱입니다. 심사자가 못 들어가면
"앱이 작동하지 않는다" 로 끝납니다. 안드로이드의 `앱 액세스 권한` 과
똑같은 자리입니다.

| 칸 | 내용 |
|---|---|
| Username | (심사용으로 만든 이메일) |
| Password | (그 비밀번호) |
| Notes | 아래 문장 |

```
This app is only available to members approved by their community.
Sign in with the account above to see chat, calendar, student records,
finances and approvals. There is no additional verification step.

이 앱은 소속 공동체의 승인을 받은 사용자만 이용할 수 있습니다.
위 계정으로 로그인하시면 모든 기능을 확인하실 수 있습니다.
```

> 💡 **심사 전용 계정을 따로 만드세요.** 실제 교사 계정을 주면
> 심사자가 진짜 학생 자료를 보게 됩니다. 안드로이드 때 만든 그 계정을
> 그대로 쓰시면 됩니다.

> ⚠️ **그 계정의 `status` 가 `approved` 인지 확인하세요.**
> TCS 는 가입하면 `pending` 으로 들어가고, 관리자가 승인해야 보입니다.
> 승인 안 된 계정을 주면 심사자는 빈 화면만 보고 "작동하지 않는다" 로
> 반려합니다. 관리자 → 멤버 관리에서 그 계정이 승인 목록에 있는지
> 눈으로 확인하고 올리세요.

> ⚠️ **Notes 에 "직접 가입하지 말라" 고 적으세요.** 심사자가 스스로
> 회원가입을 하면 승인 대기 상태라 역시 아무것도 못 봅니다.
> 위 영문 문단의 `There is no additional verification step.` 뒤에
> 이 한 줄을 더하세요:
>
> ```
> Please do not create a new account — new sign-ups require approval
> by a community administrator and will show an empty screen.
> ```

### 연령 등급

학생이 쓰는 앱이지만 **키즈 카테고리(Kids Category)로는 넣지 마세요.**
거기 들어가면 외부 링크·외부 결제·행동 기반 광고가 전부 막히고,
심사도 훨씬 깐깐해집니다. 일반 앱으로 두고 연령 등급 설문만

관리자가 잇는 구조라 보호자 동의 흐름이 이미 있습니다.
