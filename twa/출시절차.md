## 1. 앱 꾸러미(.aab) 만들기

1. <https://www.pwabuilder.com> 접속
2. 주소칸에 **`https://koreayjk.github.io/imessenger/`** → Start
3. 점수가 나오면 **Package For Stores** → **Android**
4. **Package ID 를 반드시 바꾸세요**

   ```
   기본값  io.github.koreayjk.twa      ✕
   쓸 것   io.github.koreayjk.tcs      ✓
   ```

   `assetlinks.json` 에 이 이름이 적혀 있습니다. 다르면 확인이 실패해서
   **주소창이 보이는 앱**이 됩니다. 한 번 올리면 영영 못 바꿉니다.

5. App name / Short name 은 `TCS` 그대로
6. **Download Package** → zip 을 받습니다

zip 안에 들어 있는 것:

| 파일 | 무엇 |
|---|---|
| `app-release-bundle.aab` | 플레이에 올릴 꾸러미 |
| `signing.keystore` (또는 `android.keystore`) | 서명 열쇠 |
| `signing-key-info.txt` | 그 열쇠의 비밀번호 |
| `assetlinks.json` | 참고용 (지문이 들어 있지만 **쓰지 마세요**, 3번 참고) |

> 🔐 **`.keystore` 와 비밀번호를 안전한 곳에 보관하세요.**
> 잃어버리면 앱 업데이트가 영영 막힙니다. **git 에 절대 올리지 마세요.**

## 2. 플레이 콘솔에 올리기

1. Play Console → **앱 만들기**
   - 앱 이름 `TCS` · 언어 한국어 · **앱** · **무료**
2. 왼쪽 **테스트 → 내부 테스트** → **새 버전 만들기**
3. `app-release-bundle.aab` 를 올립니다
4. 출시 노트 아무 거나 적고 **저장 → 검토 → 출시**

내부 테스트는 심사 없이 바로 올라갑니다. 지문을 받으려면 한 번은 올려야 합니다.

---

## 3. 지문을 받아 assetlinks.json 에 넣기 ⚠️ 가장 많이 틀리는 곳

**PWABuilder 가 준 assetlinks.json 을 그대로 쓰면 안 됩니다.**
플레이가 앱을 **다시 서명**하기 때문에, 실제로 필요한 건 플레이의 지문입니다.

1. Play Console → **테스트 및 출시 → 설정 → 앱 서명**
2. **앱 서명 키 인증서** 의 **SHA-256 인증서 지문** 복사
   (`AB:CD:EF:...` 처럼 콜론으로 이어진 64자리)
3. `koreayjk.github.io` 저장소의 `.well-known/assetlinks.json` 을 열어
   안내 문구 자리에 그 지문을 붙여넣습니다

```json
[{
  "relation": ["delegate_permission/common.handle_all_urls"],
  "target": {
    "namespace": "android_app",
    "package_name": "io.github.koreayjk.tcs",
    "sha256_cert_fingerprints": [
      "AB:CD:EF:... 여기에 붙여넣기"
    ]
  }
}]
```

4. 커밋하고 2~3분 뒤 확인:
   <https://koreayjk.github.io/.well-known/assetlinks.json>
5. 내부 테스트로 앱을 깔아 열어봅니다 → **주소창이 안 보이면 성공**

확인 도구: <https://developers.google.com/digital-asset-links/tools/generator>

**앱 콘텐츠** 와 **스토어 등록정보** 를 다 채워야 정식 출시 신청이 됩니다.

### ⚠️ 앱 액세스 권한 — 빠뜨리면 반려됩니다

TCS 는 **로그인해야 보이는 앱**입니다. 심사하는 사람이 들어갈 수 없으면
"앱이 작동하지 않는다" 로 반려됩니다.

**앱 콘텐츠 → 앱 액세스 권한 → 전체 또는 일부가 제한됨** 에
**심사용 계정의 이메일과 비밀번호**를 적어 주세요.
(심사용으로 교사 계정 하나를 따로 만들어 두시는 게 안전합니다.)

### ⚠️ 데이터 보안 설문 — 실제와 일치해야 합니다

TCS 가 실제로 모으는 것입니다. 빠뜨리면 적발 시 앱이 내려갑니다.

| 종류 | 모음 | 비고 |
|---|---|---|
| 이름 | ✔ | 가입 시 |
| 이메일 | ✔ | 계정 |
| 생년월일 | ✔ | 가입 시 |
| 전화번호 | ✔ | 보호자 연락처 |
| 사진 | ✔ | 증명사진·첨부 |
| 메시지 | ✔ | 채팅 |
| 기타(학적·출결·재정) | ✔ | 학생 기록 |

- 전송 중 **암호화됨** (HTTPS) → 예
- 사용자가 **삭제 요청 가능** → 예 (`delete-account.html`)

### 사용자 제작 콘텐츠(UGC) 설문 — 셋 다 **예**

채팅이 있으므로 구글은 신고·차단·조정 수단을 요구합니다. 2026-10-12 에
실제로 만들었습니다. (`db/신고차단_DB설치.sql` 을 먼저 실행해야 합니다)

| 설문 | 답 | 앱의 어디에 있나 |
|---|---|---|
| 사용자/콘텐츠를 **차단**하는 기능 | **예** | 내 프로필 → 🚫 차단 목록 · 신고창의 '앞으로 보지 않기' |
| 사용자/콘텐츠를 **신고**하는 기능 | **예** | 메시지 위 🚩 → 사유 7종 + 자세한 내용 |
| **채팅 조정** | **예** | 교직원의 🙈 가리기 · 운영관리 → 🚩 신고함에서 가리기/삭제/처리 |

> ⚠️ 설문은 **실제 코드와 일치해야** 합니다. SQL 을 아직 실행하지 않았다면
> 기능이 동작하지 않으므로, 실행한 뒤에 '예' 로 답하세요.

### ⚠️ 대상 연령 — 신중히

학생이 쓰는 앱입니다. **13세 미만이 쓰면** 'Families 정책' 이 걸려
심사가 훨씬 까다로워집니다.

- 학생 계정을 **관리자가 대신 만들고** 학생이 직접 가입하지 않는다면
  → 대상을 **13세 이상**(또는 성인)으로 두는 편이 맞습니다
- 어린 학생이 직접 쓸 거라면 → Families 정책을 따로 확인해야 합니다

## 6. 앞으로 업데이트할 때

웹은 그대로 고치면 됩니다 — **앱을 다시 올릴 필요가 없습니다.**
TWA 는 웹을 그대로 보여주기 때문입니다.

앱을 다시 올려야 하는 경우는 이것뿐입니다:

- 앱 **아이콘·이름**을 바꿀 때
- 주소(도메인)가 바뀔 때

그때는 PWABuilder 에서 **버전을 올려** 다시 뽑고, **같은 keystore 로 서명**해야 합니다.
